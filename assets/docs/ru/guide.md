# Руководство chkrootkit GUI 1.0.0

Приложение объединяет локальные проверки GNU/Linux и помогает разобрать их вывод. Оно показывает признаки, которые стоит проверить администратору. Отсутствие предупреждений не исключает заражение; подозрительная строка требует проверки причины.

## Первая проверка

1. Откройте **Инструменты**. Установите chkrootkit, rkhunter, unhide или Lynis из репозитория своего дистрибутива. Сохраняйте полный комплект утилиты с её вспомогательными файлами.
2. На вкладке **Проверка** выберите инструмент. Прочитайте описание и проверьте, что исполняемый файл найден.
3. Для chkrootkit укажите **Каталог сканирования**. `/` означает текущую систему. `/mnt/system` может быть корнем предварительно смонтированной системы; процессные проверки всё равно относятся к работающему ядру. Другие инструменты в этом приложении проверяют текущую систему.
4. Нажмите **Запустить проверку**. Окно polkit запросит разрешение на запуск отдельного сервиса с правами root. Пароль не передаётся Flutter-приложению.
5. Дождитесь завершения или нажмите **Остановить**. Длительность ограничена десятью минутами.
6. Сравните **Разбор**, **Вывод** и вкладку **Находки**. Учитывайте код завершения, ошибки запуска и пропущенные тесты.
7. Нажмите **Экспорт .log**, укажите полный путь к новому файлу. Существующий файл сохраняется без перезаписи.

## Права и параметры запуска

chkrootkit, rkhunter и unhide запускаются с root, включая установку в `~/.local/bin`. Lynis допускает ограниченный аудит без root. В дополнительных параметрах можно изменить рабочую папку процесса; обычно подходит автоматический каталог реального исполняемого файла.

**Оставлять headless-сервис запущенным** позволяет повторно использовать уже открытый сеанс до закрытия приложения. Выключение завершает его; следующая операция запрашивает права заново. Автозагрузка системного демона не устанавливается.

Разрешение запуска сервиса из пользовательского каталога предназначено для разработки. Такой каталог может изменяться обычным пользователем, поэтому для штатной установки используйте пакет и каталог с владельцем root.

seatd обеспечивает доступ композитора к устройствам. Для запроса административных прав нужны polkit, pkexec, D-Bus и запущенный агент polkit.

## Анализ через модель

На вкладке **Находки** раскройте **Анализ через API**. Создайте пароль для новых баз или разблокируйте существующие. Выберите GPTunnel либо OpenAI compatible, задайте адрес сервера, модель и API-ключ. Для GPTunnel используется `https://gptunnel.ru/v1`.

Перед отправкой проверьте лог: весь вывод будет передан выбранному серверу и может содержать имена файлов, пользователей и адреса. Нажатие кнопки отправки запускает платный запрос согласно условиям провайдера. Ответ модели оформляется как Markdown и требует ручной проверки. Ссылки копируются в буфер обмена; внешние изображения автоматически не загружаются.

Сохранение ключа включается отдельно. **Сохранить API** без этой опции сохраняет адрес, модель и провайдера. Статус под полем показывает, загружен ли ключ. HTTP 401 обычно связан с ключом или авторизацией; наличие баланса само по себе не авторизует запрос.

## Оформление и язык

В верхней панели выберите русский или английский язык, светлую, тёмную или системную тему и цвет акцента. Настройки сохраняются для следующих запусков. Системные цвета необязательны; matugen для ручной палитры не нужен. Вывод утилит и уже полученные ответы сохраняют исходный язык.

## Если проверка не запускается

- Проверьте установку сканера и его вспомогательных файлов.
- При ошибке авторизации проверьте агент polkit и D-Bus в текущем сеансе.
- Для chkrootkit оставьте рабочий каталог автоматическим; при ручном выборе там должны быть `chkproc`, `strings-static` и другие помощники.
- Проверьте существование и доступность каталога сканирования. Значение передаётся отдельным аргументом, без shell.
- После сбоя сохраните `.log`, укажите версию сканера и код завершения при обращении за помощью. Удалите личные сведения перед публикацией.
